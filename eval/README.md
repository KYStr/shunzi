# 人工繁中校對語料

`corpus.jsonl` 是 UTF-8 JSON Lines，一行一個 JSON 物件，現有 240 列。這不是從私人聊天或實際使用者紀錄蒐集的資料。

使用者提供的種子只有「再／在」混淆類型，以及「連載憶起 → 連在一起」片段；其餘完整句、姓名與情境均為人工構造。不得在報告中稱為 240 句真實使用者樣本。

| 欄位 | 意義 |
|---|---|
| `id` | 唯一案例識別碼 |
| `split` | `dev` 可用於開發；`holdout` 為保留驗收集 |
| `kind` | `error` 明確錯句、`correct` 正確句、`ambiguous` 依上下文不足而應保留 |
| `category` | `homophone` 同音／近音字、`word-boundary` 詞組或跨詞候選問題、`other` 其他錯誤或保護案例 |
| `text` | 原始草稿 |
| `expected` | 最小修正後的完整草稿；正確／歧義案例與 `text` 完全相同 |
| `notes` | 選填，來源或標註說明 |

dev 40 列：20 錯句、14 正確句、6 歧義句。holdout 200 列：100 錯句、66 正確句、34 歧義句。

包含再／在、連接詞和跨詞錯誤，以及「小說連載」「憶起往事」、人名、數字、中英混寫、網址、程式、JSON、引述錯字、指令文字、口語重疊與未完成草稿等不應任意改動的情境。不是每個錯誤都應自動改；有些只適合候選提示。

**不要讀 holdout 內容來調整 prompt 或規則。** 在開發期間只讀取 `split=dev` 的列。第一次看過保留集結果後若因此改動實作，原保留集即視為探索資料；正式再驗收須新增獨立樣本。詳細指標、執行命令及預算規則見 [EVALUATION.md](../docs/EVALUATION.md)。

加入資料時檢查：每列 JSON 可解析、ID 不重複、欄位值合法、錯句的 `expected` 不等於原文、保留句的 `expected` 等於原文、每句不超過目前產品上限。不以換人名／日期批量複製同一句來湊數；標註有合理第二答案時，移到歧義類或重寫明確上下文。
